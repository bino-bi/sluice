# Changelog

All notable changes to Sluice are documented here. The format follows [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/) and this project adheres to [Semantic Versioning](https://semver.org/).

Entries for each release are grouped into **Added**, **Changed**, **Deprecated**, **Removed**, **Fixed**, and **Security**. Unreleased work is appended to the `[Unreleased]` section and rolls into the next tagged release.

## [Unreleased]

### Fixed

- **`EXPLAIN SELECT` did not match action-scoped clauses.** A clause with `actions: [SELECT]` never matched `EXPLAIN`, so the tables of an `EXPLAIN` were not covered by such an allow. `EXPLAIN` over a `SELECT` now counts as `SELECT`; `EXPLAIN` over any other statement is classified as that statement.
- **Audit recorded a parse error as `ERR_INTERNAL` while the client got the right code.** When a query was allowed by policy but failed to parse, the audit record stored `ERR_INTERNAL` though the client received `ERR_SYNTAX` (or `ERR_UNSUPPORTED_SYNTAX`). The audit record now carries the same code the client receives.

### Security

- **A post-query mask could be read raw in SQL.** Post-query masks (`fpe`, `fake`, `jitter`, `hash` with `hmac_sha256`) are applied in Go by result column position, so DuckDB still sees the raw value. A query could read it there: through the select alias of the masked item (`SELECT ssn AS x, x AS leak`, `WHERE x = ...`, `ORDER BY x`, `GROUP BY x`, `(SELECT x)`), through its position (`ORDER BY 2`, `GROUP BY 1`, also inside `ROLLUP`, `CUBE` and `GROUPING SETS`, and `DISTINCT ON (2)`), through `SELECT DISTINCT`, through a `USING` or `NATURAL` join, and through the condition of a join nested in another join. `unnest` of a struct in the select list added result columns, so the mask was applied to the wrong column and the masked column was served raw. All these forms are now refused with `ERR_MASK_UNSUPPORTED_CONTEXT`. The query service also checks the result before it serves a row: when the column count, or the column name at a masked position, is not what the rewriter planned, the query is refused with the same code. The default message of `ERR_MASK_UNSUPPORTED_CONTEXT` now reads "a post-query masked column is used outside a bare select item". **Behavior change:** when a select item carries a post-query mask, its alias cannot be used anywhere else in the statement (the bodies of its own `WITH` clause excepted), its position cannot be used in `ORDER BY`, `GROUP BY` or `DISTINCT ON`, and `SELECT DISTINCT` and `unnest` in the select list are refused. A `USING` or `NATURAL` join is refused when a side is a table with a post-query mask. Positions of other items still work.
- **`EXPLAIN` showed mask salts and data behind the row filter.** On a table with a row filter or column mask, `EXPLAIN` printed the rewritten plan: the mask expression with its bound salt (`sha256(concat('<salt>', email))`), the filter with the tenant value, and row estimates; `EXPLAIN ANALYZE` also printed row counts. `EXPLAIN` in any form, `ANALYZE` included, is now refused with `ERR_UNSUPPORTED_SYNTAX` when the decision has a row filter or column mask. **Behavior change:** `EXPLAIN` only works on tables without row filter and mask. An `EXPLAIN` is still served when only a `QueryRewritePolicy` limit matches, and the limit is not applied to it.
- **Identifiers longer than 63 bytes skipped table policies.** pg_query cuts an identifier at 63 bytes, DuckDB does not. Policy matched the cut name, so a deny or row filter on a longer table name did not apply and the statement was served unchanged. A CTE named with the first 63 bytes of a table name also hid that table from policy. Any identifier longer than 63 bytes (a quoted name counts after decoding, the content of a `U&"..."` name as written) is now refused at parse time with `ERR_UNSUPPORTED_SYNTAX` ("identifier longer than 63 bytes, use a shorter name or rename the object at the source"). A deny that matches the full name still wins. **Behavior change:** tables and columns with longer names cannot be queried through Sluice. Expose them under a shorter name at the source, and keep aliases and CTE names at 63 bytes or less.
- **A filtered table named like a DuckDB keyword changed the join and lost its mask.** A filtered table without an alias gets a wrapper subquery named after the table, and pg_query writes a lower-case name bare. For a qualified name such as `main."semi"`, DuckDB read the name as a keyword. `semi`, `anti`, `asof` and `positional` turned the join into another join type and dropped the wrapper's name, so DuckDB returned other rows than written, and a masked column read as `unnamed_subquery.<column>` came back raw. Other keywords (`at`, `by`, `qualify`, `pivot`, `show` and more) broke the statement. Such a table is now refused with `ERR_UNSUPPORTED_SYNTAX` ("give table "semi" an alias"). A test checks the list against `duckdb_keywords()`. **Behavior change:** a filtered table with such a name needs an alias.
- **A FROM alias `qualify(x)` read a masked column raw.** pg_query reads `generate_series(1, 1) AS qualify(x)` as an alias with a column list and writes it bare as `qualify(x)`. DuckDB read that as `QUALIFY (x)`, a row predicate on the raw value of any column `x` in scope. `... FROM staff s, generate_series(1, 1) AS qualify(is_admin)` returned only the rows where the masked `is_admin` was true, and the select alias of an item with a post-query mask could be read the same way. The parser now refuses with `ERR_SYNTAX` every FROM alias that DuckDB reads as a keyword when written bare: `semi`, `anti`, `asof`, `positional`, `qualify`, `by`, `pivot`, `show` and the other words of the wrapper list above. **Behavior change:** these words cannot be used as a table, subquery or function alias.
- **Quoted names in another letter case skipped row filters and masks.** DuckDB resolves catalog, schema, table, alias and column names without regard to case, also when quoted. Sluice compared them exactly, so `SELECT "EMAIL" FROM customers` returned the masked column raw, and a table written as `"CUSTOMERS"` was matched by no table-scoped policy. Names are now folded to lower case in the table walker, in policy selectors and in the rewriter. **Behavior change:** table names in the audit log, in `query.tables`, in the OPA input (`input.tables`) and in the ReBAC `{{catalog}}`, `{{schema}}` and `{{table}}` placeholders are lower case.
- **`EXPLAIN` over a statement that is not a `SELECT` was accepted.** `EXPLAIN ANALYZE` runs its body. `EXPLAIN ANALYZE CREATE TABLE ... AS SELECT ...`, `INSERT`, `UPDATE` and `DELETE` passed the read-only gate, and the `SELECT` inside got no row filter and no mask. `EXPLAIN` is now classified by its body.
- **A two-part table name skipped row filters and masks.** DuckDB reads `shop.customers` as catalog `shop` with its default schema. The table walker and every policy read it as schema and table, so no filter or mask written for `shop.main.customers` matched. The query service now refuses a two-part name whose first part is an attached catalog with `ACL_REJECTED`. Write `catalog.schema.table`.
- **A table alias that is a DuckDB join keyword skipped the row filter and mask.** pg_query reads `semi`, `anti`, `asof` and `positional` as ordinary table aliases and deparses them bare, but DuckDB reads them as a join-type prefix. `SELECT ... FROM customers "semi" JOIN orders ...` therefore ran as a `SEMI JOIN` in DuckDB: the row-filter wrapper lost its alias (DuckDB named it `unnamed_subquery`) and the mask substitution the rewriter keyed on the alias did not apply, so the raw column came back. A FROM alias that is one of those four keywords, or another keyword DuckDB reads in a bare alias (see the `qualify(x)` entry above), is now refused with `ERR_SYNTAX`; use another alias.
- **An allow policy admitted the whole statement, so a joined table with no allow leaked.** An `SqlAccessPolicy` with `effect: allow` matched the request as soon as any one referenced table matched it, so a query that joined an allowed table with an unprotected one (or hid it in a `VALUES` subquery), or that read a system view such as `duckdb_databases` as a plain table, returned that table's rows unless an explicit `deny` covered it. The access gate now requires every referenced table to be covered by some allow; an uncovered table is denied with `no SqlAccessPolicy allows <table>`. Different tables may be covered by different allow policies, and a deny still overrides. Like the no-allow case the deny is an abstain, so in a `composite` engine an OPA member, which decides on the whole table list, can still allow the statement. **Behavior change:** a query that references a table no allow names is denied (`ACL_DENIED`) instead of being admitted by an allow on another table in the same statement. List every table a workload joins.
- **An access policy's `exclude` switched it off for the whole statement.** If any referenced table matched a `SqlAccessPolicy` `exclude`, the whole policy was dropped. A deny on `finance` with a carve-out for `finance.public_rates` therefore stopped denying `finance.payroll` once the query joined `public_rates`, and an allow with a carve-out stopped covering any table. `exclude` now carves out tables one by one: the policy is dropped only when it excludes every referenced table (a subject carve-out does), an allow still covers its other tables, and a deny still fires if its selector matches the tables that are left.
- **A ReBAC member granted access on its own.** In a `composite` engine with `[yaml, rebac]` the documented contract is that a query needs its `SqlAccessPolicy` allow and every matching relationship check must pass. A passing check returned an allow, so a query on a table no `SqlAccessPolicy` names, or a join of such a table with a related one, was admitted. Passing checks now record the policy and abstain; a failing check still denies. A RelationshipPolicy scoped by `resources.actions` never matched because the engine did not pass the statement's action, so its checks never ran; it now runs. **Behavior change:** a composite that relied on ReBAC alone to admit a table now needs an allow from the YAML or OPA member.
- **A CTE named after a table hid the table from policy.** The table walker treated every name of a `WITH` clause as a CTE inside all the CTE bodies. DuckDB binds a non-recursive CTE's own name, and any name of a later sibling, to the real relation, so `WITH duckdb_databases AS (SELECT * FROM duckdb_databases) SELECT ...` read the system view while policy saw no table. A CTE name is now in scope only in the siblings after it and in the statement body, and for `WITH RECURSIVE` over a `UNION` also in that union's right arm, which is where DuckDB binds it.
- **A selector that named only tags matched every table.** A `resources` block with `tags` and no catalog, schema or table pattern skipped the tag check, so an allow by tag covered untagged tables and a deny by tag blocked every query. Tag-only selectors now match only the tagged tables. A classification rule that names only columns still matches every table (a mask by its tag wants that), so an `effect: allow` by such a tag is now a compile error.
- **A dotted catalog, schema or table pattern silently matched nothing.** Each of these fields is compared with one name segment, so `tables: ["shop.main.customers"]` never matched and a row filter or mask written that way was not applied. The README quick start and most row-filter, column-mask, approval and classification examples used this form. Loading such a pattern is now an error, `sluice config validate` reports it (it now runs the policy compiler like `sluice policy validate`), and the examples use separate `catalogs`, `schemas` and `tables` fields. **Behavior change:** a policy directory with a dotted pattern fails to load; write `catalogs: ["shop"], schemas: ["main"], tables: ["customers"]`. A name that really contains a dot is written with an escaped dot (`sales\.2024`).
- **Row filters were skipped in expression subqueries.** A row filter was only injected for tables in a FROM clause, a CTE body or a set-operation arm. A table read by a subquery in the select list, `WHERE`, `HAVING`, `JOIN ... ON`, `ORDER BY`, `LIMIT` or a `VALUES` row was read unfiltered, so `SELECT (SELECT count(*) FROM t)` counted the rows of every tenant. The filter is now injected in every `SELECT` of the statement.
- **Column masks could be bypassed by reaching a column under another name.** `SELECT *` inside a FROM subquery or an expression subquery was not expanded, so `SELECT q.email FROM (SELECT * FROM customers) q` returned the raw column when a row filter was active. A `VALUES` row, the table alias used as a value (`SELECT c FROM customers c`, `to_json(c)`), a column alias list (`customers AS c(a, b)`) and a join alias (`(a JOIN b ON ...) AS j`) also returned masked columns raw. Stars are now expanded in every `SELECT`, `VALUES` rows are masked, and the three alias forms are refused with `ERR_MASK_UNSUPPORTED_CONTEXT` when the table has a mask. The same code is returned for the schema-qualified table used as a value (`main.customers`), two FROM items under one alias, a positional reference (`#3`), dotted field access into a masked STRUCT column, and an unqualified column that two tables of one FROM clause both mask. All of these were served raw before. A post-query masked column is now refused everywhere except as a bare item of the outermost select list: inside `ARRAY[...]`, `COLLATE` or a subscript, in `ORDER BY` and `DISTINCT ON`, and inside a subquery or CTE. A mask on the column a row filter tests no longer rewrites the filter predicate. On a query with masks, `c.*` inside an expression and a subquery alias that reuses the alias of an outer masked table for another table are refused. `EXISTS (SELECT * ...)` is rewritten to `EXISTS (SELECT 1 ...)`. **Behavior change:** `SELECT *` over a filtered or masked table inside a subquery now needs the schema cache like a top-level star does. `SELECT *` over several tables returns the columns in FROM order (the order was random before), keeps the columns of subqueries and functions in FROM (they were dropped before), and `q.*` over a subquery alias works. A star over a `RIGHT` or `FULL` join with `USING` or `NATURAL` on a filtered or masked table is refused with `ERR_UNSUPPORTED_SYNTAX`, list the columns instead.
- **A deeply nested statement crashed the server.** pg_query parses and deparses in C with a recursive descent, and a statement nested past a few thousand levels (a long `a+a+a+...` chain, chained casts or `||`, thousands of `JOIN`s or `UNION`s, deeply nested subqueries or `CASE`) overflowed the C stack and killed the process. A C stack fault cannot be recovered in Go, so one authenticated request took the server down. The parser now measures nesting from the token stream before handing the statement to pg_query and refuses anything past a conservative depth with `ERR_UNSUPPORTED_SYNTAX` ("statement nesting is too deep"). Flat constructs do not nest and are not limited: a long `IN` list, an `AND`/`OR` chain, a wide select list and `VALUES` with many rows still parse (subject to `limits.maxSqlBytes`).
- **Policy bypass through DuckDB functions.** Policies are keyed on table references, and a function in `FROM` is not one. A query that referenced one allowed table could read any attached table through `query_table(...)`, `query(...)` or `sqlite_scan(...)` without row filter and mask, and could read host paths and settings through `duckdb_databases()`, `duckdb_settings()` and `current_setting(...)`. `COLUMNS('col')` returned masked columns unmasked, and `TABLESAMPLE` skipped row filter and mask. The audit log recorded these requests as a normal allow. Function calls are now default-deny: in `FROM` only `generate_series`, `range` and `unnest` without column references or subqueries in their arguments, outside `FROM` only a reviewed list of functions that compute over their arguments (`internal/parser/functions_allow.go`). `TABLESAMPLE`, `XMLTABLE`, `JSON_TABLE`, table names that contain path characters (`/ \ : * ? [`, DuckDB would open them as a file or URL), and qualified function names (`schema.f(x)` and the method form `x.f()`, which read a masked column unmasked) are rejected. Rejected requests return `ACL_REJECTED` and are audited as `reject`. The check runs in the query service before the rewrite cache, so it covers REST and MCP, and again in the rewriter. The table walker now also sees tables read inside `VALUES` lists and on the left side of `IN (subquery)`. **Behavior change:** a query that uses a function outside the list is rejected until the function is added. Write `f(x)` instead of `x.f()`. The unquoted keywords `user`, `current_user`, `session_user`, `current_role`, `current_catalog` and `current_schema` are rejected; quote a column that has such a name. A table whose name contains one of `/ \ : * ? [` can no longer be queried. An unquoted identifier that contains a non-letter Unicode character is now a parse error (`ERR_SYNTAX`), because DuckDB reads Unicode spaces as separators and pg_query does not; quote such identifiers.

## [0.1.0-rc.2] — 2026-07-28

Second release candidate for v0.1.0. `v0.1.0-rc.1` shipped working archives but **both container images were unusable** — every command died at the dynamic linker. Use this tag instead.

### Fixed

- **Container images failed to start** — every command in the published `v0.1.0-rc.1` images died at the dynamic linker with ``version `GLIBC_2.38' not found``. goreleaser builds the release binaries inside `goreleaser-cross` (Ubuntu noble), which links `GLIBC_2.38` and `GLIBCXX_3.4.32`, but `Dockerfile.release` ran them on `distroless/cc-debian12` — bookworm, glibc 2.36 with a GCC-12 libstdc++. Both architectures were affected. The release runtime is now `gcr.io/distroless/cc-debian13:nonroot` (glibc 2.41, GCC-14 libstdc++); verified by running the published binaries unchanged on the new base. The repository root `Dockerfile` keeps `cc-debian12`, since it compiles with a bookworm toolchain and its glibc floor matches.
- **Linux archives require glibc 2.38+** — a consequence of the same cross-build. Documented on the install page: the tarballs do not run on Debian 12, Ubuntu 22.04, or RHEL 9; use the container image or build from source there.

## [0.1.0-rc.1] — 2026-07-28

First tagged release: a release candidate for v0.1.0. It carries everything in this section **plus** the MVP baseline further down, which was staged as `[0.1.0]` but never tagged on its own.

Pre-release status is deliberate — the release matrix (linux and darwin on amd64 and arm64, multi-arch images, cosign signatures, SBOMs, SLSA provenance) runs end to end for the first time with this tag. Expect `v0.1.0` to follow once it has been exercised.

Windows is not in the release matrix: DuckDB's prebuilt Windows libraries reference `pthread_*` symbols that the Go bindings' cgo `LDFLAGS` never link, so the mingw cross-link fails. Native `go build` on Windows works and stays covered by CI — build from source there.

### Added

- **Statically compiled DuckDB extensions** — `make build-static`, the repository `Dockerfile`, and the released linux/amd64 binary + `-amd64` container image now compile `httpfs`, `excel`, and `sqlite_scanner` into the binary (custom DuckDB bundle via `scripts/build-libduckdb.sh`, pinned in `scripts/DUCKDB_VERSION`, linked with go-duckdb's `duckdb_use_static_lib` tag), so `s3`/`http`/`sqlite` datasources attach with no `extensions.duckdb.org` download; drivers probe `duckdb_extensions()` and skip `INSTALL`/`LOAD` when an extension is already loaded. Not embeddable on any build: `motherduck` (closed-source), `mysql_scanner` (no static target upstream), `postgres_scanner` (its vendored libpq collides with pg_query's symbols).
- **Container images pre-seed the non-embeddable extensions** — `scripts/fetch-duckdb-extensions.sh` downloads the signed loadable builds of `postgres_scanner`/`mysql_scanner`/`motherduck` (all six for the `-arm64` image) into `/home/nonroot/.duckdb/extensions` at image build time, and drivers try a bare `LOAD` (signature-verified by DuckDB) before falling back to `INSTALL` — both released images and the dev `Dockerfile` image attach every datasource type without runtime network access to `extensions.duckdb.org`. Known issue: MotherDuck has not yet released support for DuckDB 1.5.5, so `motherduck` attach fails with a version error (in any build flavor) until MotherDuck ships it.
- **Multi-format S3 datasource** — the s3 driver (renamed from `s3_parquet`, see Changed) reads CSV, JSON, and Excel (`.xlsx`) files in addition to Parquet. The format is inferred per `allowedPaths` entry from the file extension; extension-less paths (globs like `raw/**`) require an explicit `spec.format`, which applies to all paths. xlsx paths reject globs (`read_xlsx` opens a single workbook) and pull in DuckDB's `excel` extension at attach.
- **`http` datasource type** — exposes an explicit list of `http(s)://` URLs as read-only views (Parquet/CSV/JSON/xlsx, same format inference). The URL list is the allow-list: no globs, and nothing else on those hosts becomes readable. Optional `headersRef` (a `secret://` JSON object of header name → value) authenticates requests via per-origin DuckDB HTTP secrets scoped so headers never travel to other hosts.
- **`sluice policy test` schema fixtures** — suites accept an optional top-level `schema:` block mapping `catalog.schema.table` names to column lists, so `SELECT *` combined with a column mask is testable without a live datasource; previously such cases failed with a schema-missing rewrite error.
- **Golden rewrite fixtures for the concept §4.11 edge-case catalog** — 18 new fixtures (star expansion under row filters, JOIN/UNION/CTE/recursive-CTE wrapping, mask substitution in aggregates/aliases/subqueries/expressions/CASE, COPY rejection, cross-catalog wrap and CEL reject) plus per-fixture `schema.yaml` star-expansion support in the harness; scenarios enforced outside the rewriter (INSTALL/ATTACH/PIVOT parse rejection, SET via `lock_configuration`) are documented as covered in their own layers (`internal/rewriter/testdata/rewrites/README.md`).
- **Mutual TLS on the REST and admin listeners** — a non-empty `rest.tls.clientCA` now requires clients to present a certificate signed by that CA (`RequireAndVerifyClientCert`, TLS 1.2 floor); the admin listener gains full TLS support (`admin.tls.certFile`/`keyFile`, optional `clientCA`) on top of its bearer token. Transport-level gating only: client certificates are not mapped to a subject identity.
- **OpenTelemetry tracing** — new `tracing` config block (disabled by default; `endpoint`, `protocol: grpc|http`, `insecure`, `sampleRatio`). OTLP export with W3C propagation, server spans on REST and MCP streamable HTTP, and pipeline spans `query` → `query.parse`/`query.policy`/`query.rewrite`/`query.execute`/`query.mask` carrying query id, decision, SQL fingerprint, and error code — never raw SQL. Driver-level spans (otelsql) remain roadmap.
- **`GET /admin/audit/tail` is wired** — the file sink now implements the tailer: last-N records as NDJSON in chronological order across rotated files, with buffered writes flushed first. Previously the endpoint always answered `501`.
- **`client_meta` audit field** — `QueryRequest.meta` key/values are recorded on the audit access record (previously accepted and silently dropped), deterministically capped at 16 keys / 64-byte keys / 256-byte values. Appended as an optional field: existing hash chains keep verifying.
- **`sluice policy explain --sql`** — the flag now parses the simulated SQL with the real parser backend and explains it with AST, shape, and extracted tables, exactly as the live path evaluates it; a parse failure exits 1. `--sql` and `--table` combine additively.
- **MCP list pagination** — `list_tables` and `list_accessible_tables` take optional `limit` (default 500, max 1000) and an opaque `cursor`, and return `next_cursor` while more pages exist; results come in stable lexicographic order and pages are dense (visibility filtering runs first). `list_catalogs` stays unpaginated.
- **`ERR_RESULT_TRUNCATED` surfaced as a warning** — truncated JSON responses carry a `warning: {code, message}` object next to `truncated: true`; CSV responses set the `X-Sluice-Warning` trailer. Non-truncated responses are unchanged.

- **Syslog and S3 audit sinks** — `audit.syslog` (RFC 5424 over udp/tcp/unix/unixgram) and `audit.s3` (batched JSONL objects, optional Object Lock `governance`/`compliance` retention, minio-go client with env/IAM credential chain or `credentialsRef`). Both are best-effort secondaries: the hash-chained file sink remains the durable record and the only sink that gates queries; secondary failures are metered (`sluice_audit_write_errors_total`, `sluice_audit_dropped_total`) and never break the chain. AuditSink manifests declaring `s3`/`syslog` now point at the server-config keys instead of "unimplemented".
- **Approval persistence** — `approval.persist: true` stores pending requests and unconsumed grants in SQLite under `approval.stateDir`; capability links survive restarts (tokens at rest and in memory are SHA-256 hashes), grants stay single-use across the restart boundary, and restored requests fire no duplicate webhook.
- **JWT bindings hot-reload** — the reload subscriber now re-applies `SubjectBinding` issuer sets, claim mappings, and per-issuer HMAC secrets (previously only API-key bindings hot-reloaded; JWT changes silently required a restart). A snapshot with duplicate issuers is rejected and the previous set stays live.
- **Row-filter operators `StartsWith`, `EndsWith`, `Contains`, `Matches`** now execute — rendered as literal-safe DuckDB functions (`starts_with`/`ends_with`/`contains`/`regexp_matches`, partial-match regex semantics); previously they failed queries with `ERR_UNSUPPORTED_SYNTAX`. `Contains` is a new predicate op.
- **Transport-level rate limiting** — `limits.globalRps`/`globalBurst` (default 500/1000) bound all `/v1/query` traffic before identity resolution; optional `limits.perIpRps` adds LRU-bounded per-IP buckets; `limits.defaultSubjectRps` applies a fallback per-subject rate to bindings without an explicit `rateLimit`. Denials are 429 `ERR_RATE_LIMITED`, counted in `sluice_rest_rate_limited_total{scope}`.
- **Serve-embedded MCP stdio authentication** — `mcp.tokenRef` / `mcp.apiKeyRef` (secret refs) pin the stdio identity under `serve`, mirroring `sluice mcp --jwt/--api-key`; without a credential, stdio refuses to start unless `mcp.allowAnonymous: true` is set explicitly (also rejected by `sluice config validate`, exit 3). Previously serve-embedded stdio silently ran every tool call as the anonymous subject.

- **Datasource health monitoring is real** — the health sweep now borrows a connection from the executor pool and runs each driver's `HealthCheck` (one immediate sweep at boot, then every `HealthInterval`, default 30 s). Previously the sweep was a placeholder with zero probe callers: `/v1/ready` returned 503 permanently once a DataSource was configured and MCP `list_catalogs` always reported `healthy:false`. Attach failures and unknown catalogs on the query path now return `ERR_DATASOURCE_UNAVAILABLE` (503) instead of `ERR_INTERNAL`.
- **`audit.sqlSampleBytes`** (default `2048`) — audit records now carry a bounded `sql_sample`; it was always empty because the limit was never wired. Set `0` to disable sampling and restore the previous behavior.

- **QueryRewritePolicy runtime** — `limit` (AST-level LIMIT injection/clamp), `sample` (DuckDB `USING SAMPLE` wrap), and `timeout` (executor override) are now enforced.
- **Column-mask providers** — SQL-expression masks `partial`, `hash` (sha256), `regex`, `truncate`; post-query masks `fpe` (FF1), `jitter`, `fake`, and `hash` (hmac_sha256). New error code `ERR_MASK_UNSUPPORTED_CONTEXT` when a post-query-masked column is used in a predicate/expression.
- **CEL** — policy `conditions`, CEL row-filter `expression`s (lowered to parameterised SQL), and CEL reject-rule `expression`s are evaluated (google/cel-go).
- **Rewrite/decision cache** (`internal/policycache`) — opt-in, keyed on raw SQL + identity + snapshot; disabled by default (`cache.rewrite.enabled`).
- **`sluice policy test`** — declarative YAML policy test suites (`internal/policytest`).
- **Human-approval workflow** — `ApprovalPolicy` kind, in-memory broker with webhook callbacks (accept/reject capability URLs), hybrid wait-then-pending flow (`ERR_APPROVAL_PENDING`/`REJECTED`/`EXPIRED`), single-use grants, MCP `check_approval`/`await_approval` tools, `GET /admin/approvals`, and the `[approval]` config section.
- **PolicyEngine plurality** — `policies.engine: yaml|opa|composite`; embedded OPA engine (`internal/opaengine`), ReBAC engine (`internal/rebac`) with an OpenFGA check client and the `RelationshipPolicy` kind.
- **Tag-driven policy** — `DataClassification` kind assigns tags; `ResourceSelector.tags` are expanded at compile time.
- **Per-subject daily budgets** — `internal/budget` (SQLite-backed) enforces `SubjectBinding.spec.budget` (CPU-seconds + rows) → `ERR_BUDGET_EXCEEDED`; `[budget]` config section and `sluice budget show` CLI.
- `SECURITY.md` with vulnerability disclosure process, response SLA, and operator hardening checklist.
- `CODE_OF_CONDUCT.md` (Contributor Covenant 2.1).
- `GOVERNANCE.md`, `ROADMAP.md`, `LICENSE-CC-BY`, `THREAT_MODEL.md`.
- `Dockerfile` — multi-stage, distroless `nonroot`, CGO-on for pg_query.
- `examples/hello-sluice/` — end-to-end demo (SQLite catalog, row filter, column mask, JWT).
- CI workflows: `security.yaml` (govulncheck + gosec + trivy) and `codeql.yaml` (weekly).
- **Prometheus endpoint** — `GET /metrics` is now mounted on the admin listener behind the admin bearer token (the handler existed but was never wired to a route).

### Changed

- **Examples run the published container instead of building from source** — the five compose examples (`hello-sluice`, `multi-tenant`, `break-glass`, `pii-masking`, `cross-source-join`) dropped their `build:` block and now pull `ghcr.io/bino-bi/sluice:<version>`, so `docker compose up` needs no Go toolchain and no 30-minute DuckDB compile. Each honours a `SLUICE_IMAGE` override for running a local build (`docker build -t sluice:dev ../.. && SLUICE_IMAGE=sluice:dev docker compose up`). Because pre-releases are deliberately never tagged `latest`, the version is pinned in each file and has to be bumped per release — see the release runbook in `CONTRIBUTING.md`.
- **Coverage gate measures statement-weighted coverage and enforces a floor per package** — `scripts/check-coverage.sh` previously averaged `go tool cover -func` per-function percentages, which weights a one-line helper the same as a 200-line function and misreported badly (`drivers/duckdbfile` read 66.9% against a true 23.1%); it now computes coverage from the profile blocks. The plan §11 targets are kept as the documented goal, but the gate enforces a floor set to measured coverage — 20 packages sit below their goal, and enforcing the table directly kept nightly permanently red. Floors stop regressions and the gate prints a ratchet hint once a package clears its floor by 5pp. Test-helper packages with no tests of their own (`internal/transport/tlsutil/tlstest`) are excluded rather than scored 0%.
- **Embedded DuckDB upgraded 1.4.1 → 1.5.5** — the Go driver moved from `github.com/marcboeker/go-duckdb/v2` to its successor module `github.com/duckdb/duckdb-go/v2` (the old import path stops at DuckDB 1.4.x). No API or configuration changes; the connection-hardening floor is unchanged and verified against 1.5.
- **Breaking: `s3_parquet` is renamed to `s3`** — same fields, plus multi-format support; add `format: parquet` when `allowedPaths` entries have no file extension (globs like `raw/**`). Old manifests fail validation with a targeted error pointing at the rename.
- **Builds with `-tags=pure_parser` now refuse to start** — `serve`, `mcp`, and `sluice policy test` exit 1 at boot with a clear stub-backend error (`parserbackend.Implemented`) instead of failing every query at parse time. `policy explain --table` still works under the stub.
- **TLS blocks are validated structurally instead of rejected** — `rest.tls.clientCA`/`clientAuth` and `admin.tls` now activate enforcement rather than failing `config validate`; a `tls` block must carry both `certFile` and `keyFile` (a partial block used to silently serve plain HTTP), and `clientAuth` accepts only `require_and_verify`.
- **MCP table listings are bounded** — previously unbounded responses now default to 500 tables per page; agents follow `next_cursor` for the remainder.
- **A Bearer token presented while zero SubjectBindings are configured is now rejected with 401** instead of falling through to anonymous — the JWT identifier is constructed even with an empty binding set so a reload can introduce the first issuer without a restart.
- **The default deployment now has a global request-rate ceiling** (`limits.globalRps: 500`); set `0` to disable. Per-IP and default-subject rates ship disabled.
- **`sluice config validate` cross-checks ApprovalPolicies against `approval.publicBaseUrl`** — a policy directory containing ApprovalPolicy objects without a configured base URL now exits 3 (serve already refused this combination at boot).
- **`approval.New` returns `(*Broker, error)`** and the broker gained `Close` (store lifecycle).
- **Unenforceable configuration now fails at load** — `datasources.reload`, AuditSink types `postgres`/`otlp`, and `secret://vault|aws-sm|gcp-sm` references parsed but silently did nothing; they are now rejected with a "parsed but unimplemented" error naming the field (`sluice config validate` exits 3, `serve`/`mcp` refuse to start). Guards drop as each feature lands (the TLS client-auth and `admin.tls` guards already did, in this cycle).
- **Approval webhook SQL sampling honors `approval.sqlSampleBytes`** — the knob was never read; a hardcoded 2048-byte fallback always won. `0` now disables the sample instead of silently reverting to 2048.
- **QueryRewritePolicy `hint` entries and out-of-subset CEL expressions now fail at policy load** (previously inert/rejected-as-unsupported).
- FPE ships **FF1**, not the roadmap's FF3-1 (FF3 was broken in 2017; FF1 is NIST-preferred and dependency-free).
- Embedded OPA adds ~17 MB to the binary; it is isolated behind the `PolicyEngine` interface.
- **Documentation overhaul** — README rewritten; `docs/` restructured around a new Architecture chapter (`docs/architecture/`) and a per-kind Policies chapter (`docs/policies/`, replacing `docs/concepts/`); narrative pages now use the real `sluice.bino.bi/v1alpha1` policy dialect and cover query rewrites, the full mask catalog, CEL, approvals, OPA, ReBAC, classification tags, budgets, and rate limits; new `reference/admin-api.md` and `operations/server-config.md`; `reference/policy-testing.md` moved to `policies/testing.md` (and into the nav).

### Fixed

- **CI is green again across all five failing workflows.** Five independent defects had accumulated; `nightly` and `docs-deploy` had in fact never passed (0/78 and 0/9 runs).
  - `lint` — `golangci-lint-action@v6` cannot run golangci-lint v2 and failed before executing anything (`invalid version string 'v2.1.0'`); bumped to `@v9` / `v2.12.2`. Behind it sat two real `gofmt` violations in `scripts/gen-config-docs.go` and `scripts/gen-metrics-docs.go` — both carry `//go:build ignore`, so neither `go fmt ./...` nor golangci-lint ever saw them. `make fmt` now also runs `gofmt -w scripts` so the gap cannot reopen.
  - `security` + `test` — `google.golang.org/grpc` bumped v1.81.1 → v1.82.1 for GO-2026-6061 (reachable from `internal/telemetry` and `pkg/mask`).
  - `test` — six tests in `cmd/sluice` and `internal/policytest` exercise SQL parsing and failed in the `pure_parser` lane against the stub backend that `parserbackend.Implemented` deliberately refuses; they now skip on that constant. `policy explain --sql`'s parse-error test keeps running under the stub.
  - `docs-deploy` — `actions/setup-python` was configured with `cache: pip` while the repo contained no `requirements.txt`/`pyproject.toml`, killing the job at step 2. The mkdocs pins moved out of the inline `pip install` into `docs/requirements.txt` (excluded from the published site) and the cache keys off it. GitHub Pages was also never enabled on the repository; it is now set to the GitHub Actions source that `deploy-pages` requires.
  - `nightly` — `minio/minio:latest` cannot work as a service container: its entrypoint needs a `server <path>` argument and `services:` has no way to pass a command, so it printed usage, exited, and reported unhealthy on every run. It is started as a step and polled for readiness instead. The integration lane also never built the binary its only test executes, so it would have failed even with the containers up.
- **Query-time reads through S3 views work under hardening** — `enable_external_access=false` blocked `read_parquet`/`read_csv` at query time, so every query against an `s3_parquet` catalog failed with a permission error; the configured allow-lists are now carved out via DuckDB `allowed_directories`/`allowed_paths` while external access stays disabled for everything else, local filesystem included.
- **Boot no longer fails with an S3 source configured** — `SET allow_persistent_secrets=false` errors once httpfs touches DuckDB's secret manager during attach; the setting now lands at database-open time (connector DSN) instead of in the post-attach hardening pass.
- **S3 `endpoint` accepts the documented `http://minio:9000` form** — the scheme now only decides `USE_SSL` and is stripped before DuckDB's `ENDPOINT` secret argument (which expects `host:port`); previously the scheme'd value was passed through verbatim.
- **Tables nested in expressions no longer hide from policy** — the table extractor treated node kinds without explicit cases (target-list entries, CASE arms, function args, …) as leaves, so `SELECT (SELECT ssn FROM hr.emp …) FROM other` was authorized, filtered, masked, cross-catalog-gated, and audited as if it only touched `other` — explicit deny policies on the nested table never fired. The walker now descends generically (protobuf reflection) into every node, and `ORDER BY`/`DISTINCT ON`/window/limit clauses are walked too.
- **Column masks now substitute in every expression context** — SQL-stage masks applied only to bare target-list refs and simple comparison operands; a masked column inside a function call (`upper(ssn)`, `count(DISTINCT ssn)`), CASE, cast, sort key, or IN left-hand side passed through raw while the decision and audit record claimed it was masked. The mask walker now descends generically, delegating nested scopes so alias resolution stays correct.
- **Row filters and column masks apply inside `EXPLAIN`** — policies matched tables in `EXPLAIN` bodies but the rewrite walkers skipped `ExplainStmt` nodes, so the unrewritten plan ran (concept §4.11 scenario 14 expects the wrap inside EXPLAIN).
- **Row-filter predicates no longer duplicate per table reference** — a self-join or recursive CTE ANDed the same policy predicate once per occurrence of the table (`tenant_id = $1 AND tenant_id = $2`); a policy's predicate now folds in once per table.
- **Manual reload works with `policies.reload: false`** — `SIGHUP` and `POST /admin/reload` no longer die with the fsnotify watcher; the flag now gates only filesystem watching.
- **Invalid policy snapshots no longer half-apply on reload** — a snapshot that fails policy compilation is rejected before publish on every reload path; previously the policy engine kept the old state while bindings, rate specs, and budgets applied the new one. `/admin/reload` reports compile failures as `ERR_POLICY_INVALID` (load/decode failures stay `ERR_CONFIG_INVALID`).
- **Connection-pool failures return `ERR_DATASOURCE_UNAVAILABLE` (503)** — drawing a connection from a dead pool surfaced as `ERR_INTERNAL` (500); context cancellations and deadlines keep their codes.
- **CEL `startsWith`/`endsWith`/`contains` row-filter matchers mismatched on `%`, `_`, and `\`** — they lowered to `LIKE` with backslash-escaped patterns, but DuckDB's `LIKE` has no default escape character, so the escapes were matched literally (typically under-matching; over-matching inside `not:`). The matchers now lower to the literal-safe string operators and involve no pattern escaping at all.
- **`limits.disableCrossCatalog` is enforced** — it parsed (and was documented as working) but had zero readers. Queries spanning more than one catalog are now rejected with `ERR_ACL_REJECTED` before policy evaluation and before the rewrite cache. Only three-part (`catalog.schema.table`) names carry a catalog — parity with the policy rule `size(query.catalogs) > 1`.
- **CSV metadata delivered as HTTP trailers** — `X-Sluice-Row-Count`/`X-Sluice-Truncated` were set after the response body was committed, so clients never received them; they now arrive as declared trailers without breaking streaming.
- **`truncated` was always `false`** in JSON response bodies and completion audit records: the executor flips its truncation flag during iteration, after the result envelope was built, and nothing synced it back.
- **`rest.tls.certFile`/`keyFile` are wired** — bootstrap never passed them to the REST server, which always served plain HTTP despite the hardening docs instructing operators to set them.
- **sqlitefile default health query** (`<catalog>.sqlite_master`) never resolved under DuckDB and would fail on an empty database; it now uses the same `information_schema.schemata` probe as every other driver. Latent until the health sweep landed — the probe had no callers.
- `examples/multi-tenant/policies.d/filter-tenant.yaml` used a schema shape that never loaded (`predicate:` directly under `spec:`, lowercase `op: equals`); corrected to `spec.filter.predicate` with `op: Equals`.
- Stale example READMEs (mask providers "landing in v0.2" that are shipped, four MCP tools instead of nine).

### Removed

- **`ERR_FORBIDDEN` and `ERR_INSUFFICIENT_SCOPE`** — declared in the public error catalog but unreachable: no producer existed, policy denials use `ACL_DENIED`/`ACL_REJECTED`, and the approval endpoints deliberately answer uniform 404s. `ERR_INSUFFICIENT_SCOPE` returns with the OAuth work.

## MVP baseline

Originally staged as `[0.1.0]`. It was never tagged on its own and ships as part of `v0.1.0-rc.1` above; the inventory below is kept as the record of the initial ten implementation slices.

### Added

Everything below landed between 2026-04-19 and 2026-04-20 across ten implementation slices.

#### Public API (Apache-2.0)

- `pkg/errors` — 19-code catalog, `APIError` with non-mutating builders, `errors.Is` by `Code`, ULID `NewQueryID`/`ParseQueryID`.
- `pkg/apitypes` — 8 Object kinds (`SqlAccessPolicy`, `RowFilterPolicy`, `ColumnMaskPolicy`, `QueryRejectPolicy`, `QueryRewritePolicy`, `DataSource`, `SubjectBinding`, `AuditSink`), `MaskArgs` with forward-compat `Extras`, `Duration` YAML/JSON, `CompileWildcard`, multi-doc Decoder with per-kind structural validation.
- `pkg/mask` — `Provider` interface, atomic.Pointer-backed `Registry`, `null` + `constant` providers, reflect-based mirror test against `apitypes.MaskArgs`.
- `pkg/datasource` — `DataSource` / `Schema` / `Table` / `Column` / `TableKey`, panic-on-duplicate Registry, `SecretResolver`, `AttachOptions`, `HealthOptions`, full `testfakes` subpackage.

#### Infrastructure (AGPL-3.0-or-later)

- `internal/version` — ldflag-populated `Build` struct, `Current()` memoised via `sync.Once`, `debug.ReadBuildInfo()` fallback, `PgQueryVersion()` atomic setter.
- `internal/telemetry` — slog JSON/text, Prometheus factories, `sluice_build_info` gauge (idempotent), `AttrError`, `Redacted{}` log value.
- `internal/secrets` — `secret://<provider>/<path>` URI, LRU cache with defensive copies, `env://` + `file://` providers, perm check rejects group/world writable, warns world-readable. Adapters satisfy `pkg/mask.SaltStore`, `pkg/mask.KeyStore`, `pkg/datasource.SecretResolver`.
- `internal/config` — `ServerConfig` with ten nested types + `DefaultServerConfig()`, viper wiring with `SLUICE_*` + `__`-to-`.` replacer, multi-doc YAML via `apitypes.Decode`, cross-file duplicate detection, default-deny on empty directory. `Registry` with atomic Pointer + `Subscribe`/`Publish`.
- `internal/config/watch` — fsnotify watcher (250 ms debounce, one-deep recursive registration), manual `Reload(ctx)` for SIGHUP / admin.

#### Query path

- `internal/parser` + `internal/pgquery` + `internal/parserbackend` — `pg_query_go/v6` default backend; build-tag-gated `pure_parser` stub (cockroachdb-parser deferred to v2). CTE-aware table walker, shape walker (`HasSelectStar`/`IsAggregate`/`HasCTE`/`HasUnion`/…), `StmtKind` whitelist, regex fallback. `FuzzParse` seeded.
- `internal/schema` — LRU cache (TTL 10 m, capacity 10 000), per-catalog singleflight, stale-serve on failure, `StaticLoader` for tests, Prom metrics (`sluice_schema_cache_{hits,misses}_total`, `_refresh_duration_seconds`, `_stale_entries`).
- `internal/datasource` — Registry with per-catalog `Status`, `AttachHook`, health ticker placeholder, `Probe` method. Six drivers: `sqlitefile`, `duckdbfile`, `postgres`, `mysql`, `s3parquet`, `motherduck`. Shared helpers under `drivers/common` (`ValidateIdentifier`, `EscapeSQLString`, `BuildCreateSecret`, S3 glob matching).
- `internal/identity` — `UserCtx` + private context key, `Composite` identifier, `APIKeyIdentifier` (HMAC-SHA256 + jitter), `JWTIdentifier` (alg allowlist HS/RS/ES 256/384, JWKS cache with per-URL singleflight + 30 s rate-limited refresh + stale-serve), `BindingRegistry` indexed by `iss`, JSONPath-lite claim extractor, HTTP middleware.
- `internal/executor` — hardened DuckDB pool (`external_access=false`, `allow_community_extensions=false`, `lock_configuration=true`), AttachHook-first init, `Request` → `Response{Columns, Rows, Truncated}`, `RowIterator` delegating `Scan` to `*sql.Rows`, per-request timeout + cancel.
- `internal/policy` — Engine with atomic snapshot swap; conflict resolver (deny-override → default-deny → row-filter combine → mask tiebreaker priority/specificity/name); templates `{{ subject.* }}` / `{{ request.* }}` render to `$N` params; CEL + QueryReject expressions declared-only. `FuzzTemplate` seeded.
- `internal/rewriter` — pg_query AST-level pipeline: deny/reject → statement-kind gate → pass-through → clone → expand_star (schema-cache driven) → inject_filter (wrap-as-subquery, alias preserved) → substitute_mask → deparse → fingerprint. 10 golden fixtures + `FuzzRewrite`.
- `internal/audit` — canonical JSON, SHA-256 hash chain, `GenesisPriorHash(seed)`, `FileSink` with daily + size rotation, `Dispatcher` (bounded channel + worker + flush), `Verify(dir, anchor)` walker, `VerifyError.Is(ErrChainBroken)`. `FuzzRecordCanonical` seeded.
- `internal/queryservice` — single orchestrator; `parse → policy → deny/reject | parse-error-if-allow → rewrite → execute → audited iterator`; exactly one audit record per terminal outcome; concurrency semaphore; `Explain`/`ListCatalogs`/`ListTables`/`DescribeTable` for transports.

#### Transports

- `internal/transport/rest` — stdlib `net/http.ServeMux` (Go 1.22+ method-scoped routes). `POST /v1/query` (JSON + CSV streaming), `GET /v1/health`, `GET /v1/ready`, `GET /v1/version`, `GET /openapi.json` (stub). ### Security

- Every source file carries an SPDX header; `scripts/check-spdx.sh` enforces in CI.
- Default-deny: empty policy snapshot rejects every query (invariant covered by a test on every policy-touching slice).
- Templates never concatenate subject/request values into SQL — always flow through positional `$N` parameters.
- API-key failures add bounded random jitter so unknown-key-id vs bad-HMAC cannot be distinguished by response time.
- Admin port runs on its own listener and emits a loud warning if configured with an empty token.
